# Flowable 核心概念与实战指南

本文档旨在介绍 Flowable 流程引擎的核心概念、关键的服务接口（Service）以及在业务场景中最常用的历史审批表。

## 1. 核心概念 (Key Concepts)

*   **流程定义 (Process Definition):** 相当于“类的定义”或“模板”。它是指在 BPMN 2.0 设计器中画好的流程图，部署到 Flowable 后生成的数据模型。例如：“请假流程V1.0”。
*   **流程实例 (Process Instance):** 相当于“类的实例化”。当某个用户发起一次“请假流程”时，系统就会创建一个对应的流程实例。一个流程定义可以衍生出成千上万个流程实例（比如张三的请假单、李四的请假单）。
*   **任务 (Task):** 流程流转过程中需要由“人”来处理的节点（UserTask）。例如“部门经理审批”、“财务复核”。
*   **执行实例 (Execution):** Flowable 用来描述流程运转的线索。如果流程只有一条主线，执行实例和流程实例是一对一的；如果遇到并行网关（例如同时分发给多个人会签），一个流程实例会产生多个子执行实例。
*   **流程变量 (Variables):** 在流程流转过程中传递的数据（如 `makerId`, `checkerId`, `amount`），用于控制流程走向（条件网关）或记录业务数据的系统快照。

## 2. 核心服务接口 (Core Services)

Flowable 采用经典的服务端 Service 架构，开发者通过注入不同的 Service 来与引擎内核进行交互。

### 🟢 RuntimeService (运行服务)
**职责：** 管理所有**正在运行**的流程实例和执行实例。
**主要用途：**
*   根据流程定义（Key）启动新的流程实例：`runtimeService.startProcessInstanceByKey("paymentCheckProcess")`
*   查询当前正在运行的流程实例信息。
*   在流程运行期间，动态设置或获取流程变量。

### 🔵 TaskService (任务服务)
**职责：** 管理所有正在运行的、需要**人工处理**的任务。
**主要用途：**
*   **查询待办列表：** 查询某个审批人当前需要处理的任务（Maker 待处理、Checker 待复核）：`taskService.createTaskQuery().taskAssignee("userId").list()`
*   **完成任务：** 审批人点击“同意”或“驳回”：`taskService.complete(taskId)`
*   **任务转办/委派：** 将任务临时转交给其他人处理。
*   **添加审批意见：** 在调用 complete 之前，写入审核意见：`taskService.addComment(taskId, processInstanceId, "同意打款，金额核对无误")`

### 🟠 HistoryService (历史服务)
**职责：** 管理所有**已经完成**的流程、节点、任务和变量数据，是实现“审计追踪（Audit Trail）”的核心。
**主要用途：**
*   **查询已办任务：** 查询某个用户曾经参与审批过的所有历史任务。
*   **查询流程轨迹：** 提取某个单据对应的完整流转时间轴（谁发起的 -> 谁一审 -> 谁二审）。
*   **数据统计与分析：** 根据历史数据计算审批时效、分析流程瓶颈环节。

*(附: **RepositoryService** 属于基础服务，主要负责读取画好的 XML 流程图，并将其部署到数据库中。)*

## 3. 对业务用户有意义的历史审批数据表

Flowable 内部有多达几十张数据表，但对于最终业务方（如审计员、财务主管、运营管理者）而言，最有业务溯源价值的数据主要集中在以下几张以 `ACT_HI_` (History) 开头的历史表中：

### 1. 业务台账表：`ACT_HI_PROCINST` (历史流程实例表)
*   **业务意义：** 单据总览表。一条记录代表一笔工单从生到死的生命周期。
*   **关键字段：**
    *   `START_TIME_`: 流程发起时间。
    *   `END_TIME_`: 流程结束时间（如果不为空，说明该流程已经彻底走完）。
    *   `START_USER_ID_`: 发起人（制单人 Maker）。
*   **业务场景反问：** *“帮我拉一下上个月一共发起了多少笔大额转账审批？平均每笔审批耗时多久？”*

### 2. 审批轨迹表：`ACT_HI_TASKINST` (历史任务实例表)
*   **业务意义：** **最核心的审计表！** 它忠实记录了业务流程中**每一个人工节点**的具体处理细节。
*   **关键字段：**
    *   `NAME_`: 任务名称（如“财务总监复核”）。
    *   `ASSIGNEE_`: 实际办理人（复核人 Checker）。
    *   `START_TIME_` / `END_TIME_`: 任务到达该节点的时间与办理完毕的时间。
    *   `DURATION_`: 在这个节点停留的时长（毫秒）。
*   **业务场景反问：** *“这笔异常打款，最后一步到底是谁复核的？他是在哪天几点几分操作通过的？这笔单据在合规部卡了几天？”*

### 3. 审批意见表：`ACT_HI_COMMENT` (历史批注表)
*   **业务意义：** 记录了审批人在处理任务时手动敲进去的文字意见（同意/驳回的缘由）。
*   **关键字段：**
    *   `USER_ID_`: 填写意见的人。
    *   `MESSAGE_`: 意见正文。
*   **业务场景反问：** *“这笔报销上周被法务打回来了，具体驳回原因是什么？”*

### 4. 历史快照表：`ACT_HI_VARINST` (历史变量表)
*   **业务意义：** 记录了流程流转当时的**关键业务数据快照**。
*   **关键字段：**
    *   `NAME_`: 变量名（如 `payment_amount`）。
    *   `TEXT_` / `DOUBLE_`: 具体的变量值。
*   **业务场景反问：** *防篡改审计必备。假设业务表单里的金额因为系统 Bug 或者恶意修改发生了变化，审计人员通过这张表可以查证：“当年这笔单据在审批流转时，流程引擎里记录的安全金额到底是多少？”*
